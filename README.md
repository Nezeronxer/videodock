# VideoDock

Открытый аналог 4K Video Downloader+ на Rust и Qt/QML для Linux, macOS и Windows. Проект в разработке: полное соответствие оригиналу ещё не достигнуто. Состояние и оставшаяся работа - в [TASK.md](TASK.md) и [матрице соответствия](docs/feature-matrix.md).

В текущей реализации полные публичные YouTube samples на 19 секунд и 10 минут 35 секунд (720p60, AAC 5.1) прошли Rust pipeline и декодирование до конца. [Текущая проверка YouTube](docs/youtube-delivery-2026-11-04.md) отделяет эти результаты от незавершённой проверки установочных пакетов. Стабильный релиз пока не заявляется; [предыдущий отчёт](docs/publish-verification-2026-11-04.md) описывает состояние до этих исправлений.

Извлечение ссылок, метаданные, очередь и передача медиаданных работают на Rust. Для анонимной проверки Google используется отдельный временный Qt WebEngine без аккаунта и пользовательского профиля. FFmpeg используется для локальной обработки и объединения уже скачанных дорожек; Python и yt-dlp в Rust-приложении не используются. Интерфейс и ресурсы написаны самостоятельно по результатам исследования оригинала через REA.

Реализованы очередь, выбор форматов, HLS/DASH, пауза и возобновление, субтитры, подписки, история, библиотека файлов, импорт/экспорт, встроенный браузер и Smart Mode. ИИ-обработка удалена вместе с моделями и элементами интерфейса; прежние результаты и история сохраняются. Наличие обработчика или кнопки не доказывает поддержку всех сценариев сайта. Подтверждённое поведение и ограничения перечислены в [каталоге сервисов](crates/media/tests/catalog/SUPPORT.md) и [карте интерфейса](crates/desktop/COVERAGE.md).

## Разработка

Нужны Rust 1.99+, Git, Qt 6 с Qt Quick, WebEngine, Widgets и Tools, CMake, Ninja, C/C++ compiler, libclang, FFmpeg и ffprobe. Git нужен сборке нативного TLS; на Windows x64 этой сборке также нужен NASM. В runtime эти инструменты не используются. На macOS/Windows нужны собственные сборка и проверка на соответствующей ОС.

На macOS нужен Homebrew `ffmpeg-full`: обычный `ffmpeg` не содержит используемый для OGG энкодер `libvorbis`. После `brew install ffmpeg-full` добавьте `$(brew --prefix ffmpeg-full)/bin` в начало `PATH` перед тестами и упаковкой приложения.

```sh
export CARGO_BUILD_JOBS=2
export CARGO_TARGET_DIR="$HOME/.cache/videodock-rust-target"
cargo test --workspace --locked
cargo run --locked -p videodock-desktop
```

Qt-проверка изолированного профиля на Linux: `sh crates/desktop/tests/check-cookie-bridge.sh`. Сетевые и тяжёлые медиаинтеграции помечены `ignored` и запускаются явно. Пример проверки всей очереди с публичным YouTube sample:

```sh
cargo test -p videodock-core --test engine_online -- --ignored
```

Скрипты сборки и установки находятся в `scripts/rust/`. Они требуют установленных зависимостей и предназначены для разработки; проверенного релиза для трёх ОС пока нет.

На Windows `build-windows.ps1` подготавливает каталог `package/VideoDock` внутри `CARGO_TARGET_DIR`. `package-windows.ps1` собирает обычный установщик через Inno Setup 7.1.1. Он устанавливает приложение для текущего пользователя, включает Qt, FFmpeg и MSVC runtime и создаёт ярлык; профили и скачанные файлы сохраняются отдельно. Полный релиз публикуется после проверки установленного приложения на Windows 10 и Windows 11. Для Linux подготовлен Flatpak x86_64; инструкция установки и фактически проверенное окружение перечислены в [отчёте](docs/linux-flatpak-qa-2026-11-05.md). Проверка macOS-поставки ещё не завершена. Подробности Windows 10/11 - в [отчёте установщика](docs/windows-qa-2026-11-05.md).

## Данные и безопасность

Настройки и SQLite хранятся локально через Qt `AppLocalDataLocation`: на Linux обычно `~/.local/share/videodock`, на macOS `~/Library/Application Support/videodock`, на Windows - локальный каталог данных пользователя. Для изолированного теста можно задать абсолютный `VIDEODOCK_DATA_DIR`. SQLite, браузерный профиль и защищённые данные должны находиться вне Dropbox. Готовые видео можно сохранять в Dropbox.

Программа использует только собственный новый профиль браузера. Cookies передаются из Qt прямо в Rust, не попадают в QML/SQLite/экспорт; срок действия сохраняется, восстановлением cookies управляет Qt. Приватные исходные ссылки и пароль прокси находятся в отдельном локальном хранилище, доступном только пользователю на Unix. Это ограничение файловых прав, не обещание аппаратного шифрования. Записи удаляются отдельно от файлов; удаление файлов требует явного выбора.

Фактические проверки Rust-версии - в [docs/rust-verification.md](docs/rust-verification.md). Свежие полные загрузки и незакрытые отказы - в [матрице стабильности 04.11](docs/stability-2026-11-04.md). Архивные документы `docs/design.md`, `docs/plan.md` и `docs/verification.md` описывают Python-прототип, сохранённый в ветке `archive/python-prototype`; к текущему Rust runtime они не относятся.

## Лицензии

Rust-приложение использует RustyPipe под GPL-3.0 и распространяется с выполнением её условий; текст - [LICENSES/GPL-3.0.txt](LICENSES/GPL-3.0.txt). Изменения зависимости перечислены в [vendor/rustypipe/PATCHES.md](vendor/rustypipe/PATCHES.md). Анонимная проверка использует [BgUtils под MIT](crates/desktop/attestation/README.md), исходники и текст лицензии включены. Старый Python-прототип и его MIT-лицензия сохранены отдельно. Лицензии Qt, FFmpeg и остальных зависимостей действуют дополнительно. Извлечённые закрытые QML/иконки/компоненты оригинала в поставку не включаются.
