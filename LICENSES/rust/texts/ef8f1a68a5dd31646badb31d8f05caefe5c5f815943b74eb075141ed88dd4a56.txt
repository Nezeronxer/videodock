// NOTE: This entire module was generated by an LLM (Gemini) as a pure-Rust port of
// ICU4C's `UMutableCPTrie` (`icu4c/source/common/umutablecptrie.cpp`), replacing the
// former `icu_codepointtrie_builder` crate's Wasm (`wasmi`) and native ICU4C FFI
// backends.
//
// Summary of implementation design and reasoning:
//
// 1. Why a direct algorithmic port of `umutablecptrie.cpp`:
//    ICU4X's `CodePointTrie` runtime representation (`CodePointTrieHeader`, multi-stage
//    `index` array, and `data` array with trailing `high_value` and `error_value`) is
//    defined by ICU4C's `UCPTrie` binary format. Producing tries that are not merely
//    functionally equivalent, but bit-for-bit identical to ICU4C across `TrieType::Fast`
//    and `TrieType::Small` and all value widths (8, 16, and 32-bit), requires following
//    the exact same compaction heuristics, block deduplication order, overlap searches,
//    null-block selection, and padding rules as `umutablecptrie_buildImmutable`.
//
// 2. Core data structures:
//    - `MutableCodePointTrie`: Mirrors ICU4C's `UMutableCPTrie`. The Unicode code point
//      space (`0..0x110000`) is partitioned into 16-code-point small data blocks
//      (`UCPTRIE_SHIFT_3 = 4`, `I_LIMIT = 0x11000` blocks). Each block has an entry in
//      `flags` (`ALL_SAME`, `MIXED`, or `SAME_AS`) and `index`:
//        * `ALL_SAME`: `index[i]` stores the uniform 32-bit data value directly without
//          allocating space in `data`.
//        * `MIXED`: `index[i]` stores the starting offset of a block in `data`. In the
//          BMP (`i < BMP_I_LIMIT`), `get_data_block` allocates 64-entry fast blocks
//          (4 consecutive 16-entry small blocks) at once to match fast-index granularity.
//        * `SAME_AS`: Used during compaction to point to an earlier identical `ALL_SAME`
//          block index.
//    - `AllSameBlocks`: A 32-entry frequency table (`AllSameBlockEntry`) used during
//      `compact_whole_data_blocks` to deduplicate `ALL_SAME` blocks and track reference
//      counts so the most-referenced uniform block can be chosen as `data_null_offset`
//      (which accelerates range iteration in `CodePointTrie`). If more than 32 distinct
//      uniform block values exist, it falls back to scanning earlier blocks and evicts
//      the least-used entry, matching ICU4C.
//    - `MixedBlocks`: An open-addressed hash table over sliding windows of length
//      `block_length` in the compacted data or index arrays. Each 32-bit table entry
//      packs the upper hash bits (`hash_code << shift`) with a 1-based array offset in
//      the low `mask` bits (reserving `0` for empty slots). Used to find exact block
//      matches in O(1) expected time before falling back to bounded suffix-prefix
//      overlap checks (`get_overlap` / `get_all_same_overlap`).
//    - `BlockElem`: A small internal trait implemented for `u16` and `u32` so that
//      `equal_blocks`, `get_overlap`, and `MixedBlocks` can operate generically across
//      both 32-bit data blocks and 16-bit index blocks without C++ `void *` casts or
//      duplicated code.
//
// 3. Compaction pipeline (`compact_trie` and `build`):
//    - Compile-time width check & masking: `CodePointTrie` only supports 1..=4 byte
//      `TrieValue::ULE` types, enforced at monomorphization time via
//      `const { assert!(matches!(size_of::<T::ULE>(), 1..=4)); }`. For 1-byte and 2-byte
//      types, `mask_values` masks stored 32-bit values to 8 or 16 bits before compaction
//      so values that become equal after truncation can be deduplicated.
//    - `high_start` computation: Scans downward from `high_start` to find the lowest
//      code point above which all values equal `high_value` (the value at `U+10FFFF`),
//      rounded up to a 512-code-point (`UCPTRIE_CP_PER_INDEX_2_ENTRY`) boundary and
//      pinned to at least the fast-index limit (`0x10000` for `Fast`, `0x1000` for `Small`).
//    - ASCII capture & whole-block pass (`compact_whole_data_blocks`): The linear ASCII
//      prefix (`0..0x80`) is read via `self.get(c)` *before* `compact_whole_data_blocks`
//      runs, because `compact_whole_data_blocks` mutates `flags[i]` to `SAME_AS` and
//      overwrites `index[i]` with block indices (which `self.get()` would misinterpret
//      as `MIXED` data offsets). `compact_whole_data_blocks` also demotes `MIXED` blocks
//      whose elements are all identical back to `ALL_SAME`, and promotes non-uniform
//      4-sub-block fast blocks from `ALL_SAME` to `MIXED`.
//    - Data compaction (`compact_data`): Populates `new_data` starting with the linear
//      ASCII block, then compacts fast-range blocks (length 64) and small-range blocks
//      (length 16) using `MixedBlocks` for full matches and `get_overlap` /
//      `get_all_same_overlap` for partial overlaps. A small-range null block is prevented
//      from aliasing the start of a fast block (`is_start_of_some_fast_block`) as required
//      by ICU4C's range-iteration logic.
//    - Index compaction (`compact_index`): When `high_start` is within the fast range,
//      the index is simply the flat 16-bit fast index. Otherwise, condenses the fast
//      index, classifies supplementary index-3 blocks (`I3_NULL`, `I3_BMP`, `I3_16`,
//      `I3_18`), encodes 18-bit index-3 blocks (packing every 8 18-bit data offsets into
//      9 `u16` words with the upper 2-bit pairs collected into the leading `u16`),
//      compacts index-3 blocks with overlap, and finally compacts index-2 blocks while
//      writing the index-1 table.
//    - Alignment and trailer values: Pads `index16` to an even length when elements are
//      >2 bytes, and appends `high_value` and `error_value` at the end of `data` (with
//      padding so total byte length is a multiple of 4, matching ICU4C's layout).
//
// 4. Rust idioms & ICU4X lint compliance:
//    - `icu_collections` enforces `#![deny(clippy::indexing_slicing, clippy::unwrap_used,
//      clippy::expect_used, clippy::panic)]` and forbids `unsafe`.
//    - Rather than suppressing `clippy::indexing_slicing` across the port, all C array
//      indexing and pointer arithmetic was translated to checked slice access (`.get()`,
//      `.get_mut()`), slice bulk operations (`.fill()`, `.copy_from_slice()`,
//      `.copy_within()`, `.ends_with()`, `.last()`), and fixed-size chunk iterators
//      (`.as_chunks::<8>()` / `.as_chunks_mut::<9>()` for the 18-bit index-3 packing
//      and `.as_chunks_mut::<SMALL_DATA_BLOCKS_PER_BMP_BLOCK>()` for condensing the
//      fast index).
//    - The only two `#[expect(clippy::unwrap_used)]` annotations are at the final
//      construction step in `MutableCodePointTrie::build`, where `T::try_from_u32`
//      round-trips values that originated from `T::to_u32` and `CodePointTrie::try_new`
//      validates the freshly built header, index, and data vectors.
//    - Output was verified bit-for-bit against ICU4C's `UMutableCPTrie` (via Wasm) and
//      all existing TOML round-trip tests in `tests/cpt.rs`.

//! This module provides a data structure for a space-efficient and time-efficient lookup of
//! sequences of 16-bit units (commonly but not necessarily UTF-16 code units)
//! which map to integer values.
//!
//! It is an implementation of the existing [ICU4C UCharsTrie](https://unicode-org.github.io/icu-docs/apidoc/released/icu4c/classicu_1_1UCharsTrie.html)
//! / [ICU4J CharsTrie](https://unicode-org.github.io/icu-docs/apidoc/released/icu4j/com/ibm/icu/util/CharsTrie.html) API.
//!
//! ## Architecture
//!
//! ICU4X [`Char16Trie`] is designed to provide a read-only view of `UCharsTrie` data that is exported from ICU4C.
//!
//! ## Examples
//!
//! ### Querying a `Char16Trie`
//!
//! ```rust
//! use icu::collections::char16trie::Char16Trie;
//! use zerovec::ZeroVec;
//!
//! // A Char16Trie containing the ASCII characters mapping 'a' to 1 and 'ab'
//! // to 100.
//! let trie_data = [48, 97, 176, 98, 32868];
//! let trie = Char16Trie::new(ZeroVec::from_slice_or_alloc(&trie_data));
//!
//! let mut cursor = trie.cursor();
//! cursor.step('a');
//! assert_eq!(cursor.value(), Some(1));
//! assert!(!cursor.is_empty());
//! cursor.step('b');
//! assert_eq!(cursor.value(), Some(100));
//! assert!(cursor.is_empty());
//! cursor.step('c');
//! assert_eq!(cursor.value(), None);
//! assert!(cursor.is_empty());
//! ```
//!
//! [`ICU4X`]: ../icu/index.html

//!
//! # Architecture
//!
//! ICU4X [`CodePointTrie`] is designed to provide a read-only view of [`CodePointTrie`] data that is exported
//! from ICU4C. Detailed information about the design of the data structure can be found in the documentation
//! for the [`CodePointTrie`] struct.
//!
//! # Examples
//!
//! ## Querying a `CodePointTrie`
//!
//! ```
//! use icu::collections::codepointtrie::planes;
//! let trie = planes::get_planes_trie();
//!
//! assert_eq!(0, trie.get32(0x41)); // 'A' as u32
//! assert_eq!(0, trie.get32(0x13E0)); // 'Ꮰ' as u32
//! assert_eq!(1, trie.get32(0x10044)); // '𐁄' as u32
//! ```

//! This module provides necessary functionality for highly efficient querying of sets of Unicode characters.
//!
//! It is an implementation of the code point portion of the existing
//! [ICU4C UnicodeSet API](https://unicode-org.github.io/icu-docs/apidoc/released/icu4c/classicu_1_1UnicodeSet.html).
//!
//! # Architecture
//! ICU4X [`CodePointInversionList`] is split up into independent levels, with [`CodePointInversionList`] representing the membership/query API,
//! and [`CodePointInversionListBuilder`] representing the builder API.
//!
//! # Examples:
//!
//! ## Creating a `CodePointInversionList`
//!
//! `CodePointSets` are created from either serialized [`CodePointSets`](CodePointInversionList),
//! represented by [inversion lists](https://unicode-org.github.io/icu/userguide/strings/properties.html),
//! the [`CodePointInversionListBuilder`], or from the Properties API.
//!
//! ```
//! use icu::collections::codepointinvlist::{
//!     CodePointInversionList, CodePointInversionListBuilder,
//! };
//!
//! let mut builder = CodePointInversionListBuilder::new();
//! builder.add_range('A'..='Z');
//! let set: CodePointInversionList = builder.build();
//!
//! assert!(set.contains('A'));
//! ```
//!
//! ## Querying a `CodePointInversionList`
//!
//! Currently, you can check if a character/range of characters exists in the [`CodePointInversionList`], or iterate through the characters.
//!
//! ```
//! use icu::collections::codepointinvlist::{
//!     CodePointInversionList, CodePointInversionListBuilder,
//! };
//!
//! let mut builder = CodePointInversionListBuilder::new();
//! builder.add_range('A'..='Z');
//! let set: CodePointInversionList = builder.build();
//!
//! assert!(set.contains('A'));
//! assert!(set.contains_range('A'..='C'));
//! assert_eq!(set.iter_chars().next(), Some('A'));
//! ```
//!
//! [`ICU4X`]: ../icu/index.html
