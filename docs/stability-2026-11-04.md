# Загрузки и устойчивость, 04.11.2026

Проверен текущий Rust runtime на Arch Linux. Полная готовность всех площадок **не достигнута**: три длинных YouTube-проверки продолжают завершаться HTTP403, часть сервисов требует новой реализации или недоступна анонимно. Успешный sample не означает поддержку всех форматов, аккаунтов, регионов и коллекций.

Охват сверён с 53 сохранёнными ParserGraph оригинала: 18 именованных сервисов и общий HTML/direct-media путь. Подтипы вроде BiliBili bangumi/audio/TV и Naver Blog не считаются проверенными по одному обычному ролику. Оригинальный исполняемый файл, аккаунты и системная сеть не изменялись.

## Что исправлено

- Прямые медиассылки используют `VideoDock/0.2` при разборе и передаче. W3C возвращал HTTP403 на прежний браузерный User-Agent и HTTP200 с идентификатором приложения. Локальная регрессия сначала воспроизвела отказ; после исправления реальный MP4 скачан и полностью декодирован.
- Для полного HTTP Range-потока запрос ограничен 1 МиБ. На одном и том же YouTube sample video CDN принимал 4 МиБ, audio CDN отвечал HTTP403; 1 МиБ принимался обоими. Это исправляет первый отказ, но **не** поздние отказы длинных YouTube-потоков.
- GET метаданных адаптивного потока, сегмента или файла повторяется не более трёх раз при 429/500/502/503/504, connect error и timeout. Между запросами действует задержка; числовой Retry-After учитывается до 30 секунд. Отмена прерывает ожидание. 401/403 не повторяются; ошибка не записывается в файл как медиаданные. Обрыв уже начатого тела остаётся ошибкой с сохранением частичного файла для обычного возобновления.
- Смена папки немедленно убирает производные записи старой библиотеки, сохраняя историю собственных загрузок. Раньше при переходе в ещё не созданную папку оставались старые complete-строки. Регрессия воспроизведена отдельно; проверка прокси теперь дополнительно выбирает именно запрошенную тестовую запись.
- Импортные тесты используют собственную папку библиотеки. Файлы из реальной пользовательской библиотеки больше не влияют на утверждения об атомарности импорта.

Новых runtime-зависимостей нет. Python/yt-dlp, внешние генераторы токенов и изменение системных маршрутов в продукт не добавлялись. Эксперимент с актуальной версией iOS-клиента не помог и полностью отменён.

## Проверки реализации

- Workspace: **162 passed / 0 failed / 42 ignored**. Ignored - отдельные сетевые и тяжёлые сценарии; они не включены в число пройденных тестов.
- `cargo clippy --workspace --all-targets --locked --offline --no-deps -- -D warnings`: exit 0.
- Свежая Linux debug-сборка `videodock-desktop`: exit 0.
- Proxy engine E2E: HTTP/SOCKS5 × с паролем/без пароля, в каждом случае HLS+subtitles+ffprobe и счётчики реальных запросов. Wrong password/dead proxy не дают прямого fallback.
- Qt WebEngine: HTTP с паролем/без пароля и SOCKS5 без пароля; неподдерживаемые конфигурации отклоняются явно.
- Qt + настоящий Engine: темы/restart, validation, settings, локальная UI-загрузка, ffprobe, durable history, контекстное копирование и безопасное удаление; 5 settings tabs, 10 dialogs, browser modes, narrow window и contrast.
- Независимый ffprobe и полное декодирование FFmpeg `-xerror` сохранённых Tumblr, BiliBili, Dailymotion, Generic, YouTube Zoo/HD: exit 0. Результаты по каждому файлу - `files-proof.json`.
- Сохранённые REA payloads перепроверены по исходному SHA-256: 18 bundles, 909 точных сравнений, длины/хеши, 199 записей QML-индекса, 1182 английских QM messages и границы ссылок отчёта.
- `git diff --check`: exit 0. Изменённые в этом проходе Rust-файлы отформатированы. Общий `cargo fmt --all --check` дополнительно видит прежнее форматирование в vendor/desktop и других существовавших правках; несвязанные файлы не переформатированы.

CUA увидел настоящее тестовое окно на отдельном профиле и снял интерфейс, но команды ввода не дали подтверждённого результата. Поэтому ручная загрузка через CUA **не засчитана**; Qt integration harness её не подменяет. Тестовый процесс закрыт, основной профиль не менялся. macOS/Windows в этом проходе не собирались и не запускались.

## Воспроизведение и доказательства

Обычные параметры сборки: `CARGO_BUILD_JOBS=2`, `CARGO_TARGET_DIR=$HOME/.cache/videodock-rust-target`.

```sh
cargo test --workspace --locked --offline
cargo clippy --workspace --all-targets --locked --offline --no-deps -- -D warnings
cargo test -p videodock-core --test catalog_downloads --offline -- --ignored --nocapture --test-threads=2
cargo test -p videodock-core --test youtube_downloads --offline complete_ -- --ignored --nocapture --test-threads=1
sh crates/desktop/tests/check-browser-proxy.sh
sh crates/desktop/tests/check-appearance.sh
```

Сетевые тесты могут завершаться ошибкой на реально недоступных площадках - это ожидаемый сигнал матрицы, а не зелёная offline-проверка. Для явно выбранного proxy маршрута harness принимает `VIDEODOCK_TEST_PROXY`; один и тот же proxy применяется к разбору и медиа. Адрес/учётные данные не печатаются. `VIDEODOCK_TEST_OUTPUT_DIR` сохраняет готовые файлы вне временного каталога.

Доказательства вне Dropbox: `~/.local/share/videodock/research/stability-2026-11-04/`.

Основные журналы: `catalog-baseline.log`, `catalog-repeat-{1,2}.log`, `catalog-proxy-repeat.log`, `bilibili-proxy.log`, `tumblr-full.log`, `generic-proxy-fixed.log`, `generic-direct-fixed.log`, `dailymotion-proxy-1.log`, `youtube-final.log`, `youtube-range-offsets.log`, `youtube-client-failure.log`, `workspace-complete.log`, `clippy-complete.log`, `desktop-build-final.log`, `browser-proxy.log`, `appearance.log`, `rea-evidence-check.log`.
