# Проверка YouTube 04.11.2026

Работа продолжается. Это результаты интегрированного production-кода, а не утверждение готовности релиза или полного соответствия 4K.

Qt выполняет только анонимную проверку Google в отдельном off-record процессе того же executable. Rust получает метаданные, исполняет player signatures и скачивает SABR/UMP. У Qt нет доступа к пользовательскому аккаунту и медиасерверу. PO и подписанные URL не сохраняются в истории, экспорте или журнале.

Реальная отмена metadata также проверена на Linux release: worker и 3 WebEngine descendants завершились за 54 мс, оставшихся процессов и zombies нет; следующий запрос в том же Rust-процессе успешно получил 14 форматов.

Для выбранных дорожек проверяются identity, непрерывная последовательность, точное число байтов и конечное покрытие времени. Незавершённый сегмент не фиксируется; повтор не удваивает данные. UMP имеет ограничения размера и отклоняет оборванный EOF. Одной объявленной длительности ffprobe недостаточно: live-тест проверяет последние декодированные timestamps.

Независимый review не выявил подтверждённых Critical/Important дефектов. Отдельно прошли ограничения IPC, malicious redirects, oversized interpreter, выбранный HTTP proxy, правильный/неправильный proxy password. HTTPS proxy и SOCKS с паролем для Qt-проверки явно отклоняются; прямой fallback при ошибке прокси отсутствует.

Финальная локальная проверка исходников: Rust workspace 204 passed / 0 failed / 42 ignored, Clippy all-targets с `-D warnings`, Linux release, Qt appearance/real Engine, browser proxy, cookie bridge, native proof boundaries и worker contracts - PASS. Ignored tests не считаются пройденными. Native Play открыл созданный локальный файл в Haruna; дальнейшее воспроизведение в этом плеере отдельно не подтверждено. Для файла независимо проверен полный FFmpeg decode. Qt-тест pointing cursor прошёл; физический Wayland cursor отдельной успешной проверкой пока не подтверждён.

Автоматический маршрут: явный proxy пользователя имеет приоритет, затем системный proxy и listener работающего известного VPN. Zapret/TUN работают через системный маршрут. DNS fallback применяется только при неуспешном обычном DNS для разрешённых публичных YouTube/Googlevideo/attestation хостов, отключается при выбранном proxy и пока поддерживает IPv4. На физическом Windows QA-маршруте DNS восстановлен, но проверенные Google IP недоступны до установки TCP-соединения; это не исправление доступа провайдера и не успешная загрузка через zapret.

Воспроизводимая проверка: ignored tests `crates/core/tests/youtube_downloads.rs` с `VIDEODOCK_TEST_PROOF_WORKER`, `VIDEODOCK_TEST_PROXY` и изолированным output directory. Проверки worker и исходники MIT-компонента описаны в [attestation README](../crates/desktop/attestation/README.md).
