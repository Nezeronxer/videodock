# Windows 10: установщик 0.2.1 и реальные загрузки, 09.11.2026

Статус: PARTIAL. Итоговый кандидат установлен и запускается, но первая Windows-попытка Shorts воспроизвела SABR stall. Полный релиз остаётся закрыт до проверки окончательного установщика на Windows 11 и остальных gates из TASK.md.

Исследовательские файлы: `~/.local/share/videodock/research/windows-regression-2026-11-09/`.

## Повреждённый runtime после прерывания

Первый финальный установщик (`feb2448f…`) запускался с `0xC000012F`. Staged и installed MSVC DLL совпадали по хешам, но имели нулевые MZ/PE заголовки. Исходные DLL Visual Studio и предыдущая рабочая QA-поставка сохранили правильные заголовки. Точная причина повреждения данных внутри ВМ не установлена. Этот установщик сохранён отдельно как `Rejected-VideoDock-0.2.1-damaged-runtime-Setup.exe` и к использованию не допускается.

Общая проверка Windows binaries вызывается перед заменой предыдущего stage и повторно перед упаковкой: проверяет MZ, границы PE offset, PE signature, AMD64 и PE32+. Файлы читаются только в области заголовков. Проверка не заменяет настоящий запуск.

Нативные проверки Windows PowerShell 5 прошли: один корректный заголовок, шесть некорректных; rollback при отказах deployment, license и повреждённом binary; отклонение фактических повреждённых CRT в старом stage. Журнал: `windows-binary-guard-green.json`. CI запускает эти проверки. Qt и CRT скопированы заново из SDK; восстановленная поставка открыла отзывчивое окно до повторной установки.

## Полные публичные загрузки

Каждый PASS означает нажатие Paste Link в установленном приложении, полный файл с видео и звуком по ffprobe, полный FFmpeg decode и сохранение строки истории после штатного перезапуска. Аккаунты и пользовательские профили не использовались.

Маршрут YouTube: изолированный QA SOCKS relay к существующему ingress 1086 с physical bind enp3s0. Реальные пользовательские proxy preferences не менялись. Длинный watch-прогон со скоростью около 208 KB/s был прерван перезапуском временного QA relay, завершившись с ошибкой соединения. Это нарушение условий проверки; его результат не используется для вывода о стабильности продукта. Свежий прогон `watch-stable` прошёл с relay на час без изменений сети: полный цикл 331.146 с, включая декодирование и restart/history. Сводное доказательство: `final-windows10-summary.json`; конкретный watch-результат: `win10-watch-stable-result.json`.

Первый отказ Shorts сохранён в `win10-final-shorts-state/`, повторный PASS его не отменяет. Сравнительный Linux-прогон через тот же ingress прошёл за 22.51 с вместе с metadata и полным decode (`host-final-short.log`). Причина непостоянного Windows-отказа ещё не установлена; дополнительное изменение SABR по этой гипотезе не внесено.

После завершения проверки установленное приложение ещё раз открыто на изолированном watch-профиле. Снимок `win10-final-watch-history.png` показывает завершённый MP4 1080p, 13:46, 221.9 MiB; окно отвечает. Это тот же файл из полного watch-доказательства.

## Открыто

- Выяснить причину первого SABR stall Shorts: следующие успешные попытки не закрывают этот дефект.
- Повторить окончательный установщик на Windows 11: ВМ ожидает обычного входа. По выбору пользователя работа пока продолжена только на Windows 10.
- Временные QA transfer и relay остановлены после завершения загрузок; порты 39709/39711 больше не слушают. Постоянный ingress 1086 не менялся.
- Gates macOS, Linux и полного соответствия остаются в TASK.md; эти Windows-результаты не доказывают готовность всего продукта.
