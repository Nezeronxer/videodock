## Последующий Rust/desktop этап

Начальные сведения выше относятся к первому статическому проходу и Python-прототипу. Текущий runtime написан на Rust/Qt; полный статус находится в [матрице](feature-matrix.md). В продолжении 03.11 оригинальный EXE запускался в отдельном пустом Wine prefix для снимка onboarding; его исходный digest не изменился. Пользовательский PortableApps launcher/Data не использовались. Доступный CUA снимал Wine окно, но его ввод не менял шаг, поэтому полного живого обхода оригинала нет. Обнаруженное расхождение обучения исправлено в собственном Qt frontend и проверено regression runner и реальным Rust бинарём. Доказательства и границы - [UI parity](ui-parity.md).

## Ручные сценарии, 07.11.2026

Сверка исходных ManualSubscriptionDownload/ManualSubscriptionDownloadFooter и ManualBatchDownloadFooter подтверждает заявленные действия Save при редактировании, скрытый Download Existing и выбор назначения из истории. Реализация этих сценариев, сохранение пользовательского Selection после асинхронного разбора и агрегирование языков уже находятся в QA candidate `96157bb`. Нативная проверка Windows EN/RU не завершилась в run `42295899298`; обновлённый run `42300259497` достиг 15-минутного предела, а отдельные журналы окна остались пустыми. Требуется диагностика старта Qt на runner; UI пока не подтверждён. Статические ресурсы оригинала подтверждают состав интерфейса, но не заменяют динамическую проверку его внутреннего загрузчика.

Отдельная проверка фактической функции VideoDock applyOutputPath воспроизвела пять ошибок с Windows путями: backslash, корень диска, UNC и смешанные разделители. Исправление ограничено Windows; пути Unix с backslash в имени сохранены. До правки пять отказов, после неё 14 checks PASS и qmllint exit 0; нативные сценарии добавлены, но ещё не выполнены в Windows.

Артефакт следующего Windows запуска `42306422460` сохранил ранний журнал: Qt не нашёл платформенный плагин `windows` ещё до создания QApplication. Поэтому отсутствие снимков относится к окружению отдельного тестового EXE, а не подтверждает расхождение UI продукта с оригиналом. В скрипт harness добавлен тот же штатный windeployqt, который уже применялся для продукта; программный renderer как неустранивший ошибку отменён. Повторная нативная проверка остаётся открытой.
