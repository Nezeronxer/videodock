# Проверка VideoDock 0.1.0

Дата: 03.11.2026. Проверено на Linux (Arch), Python 3.12.14, PySide6 Essentials 6.12.0, yt-dlp 2026.10.26. Исходники в `Проекты/videodock`, окружение вне Dropbox в `~/.local/share/videodock/venv`.

## Фактические проверки

- `python -m pytest -q`: **24 passed**. Проверены вход, ограничения качества, настройки, SQLite, восстановление прерванных заданий, защита SQL-ключей, история без удаления файлов, реальные MP4/MP3 через localhost HTTP и FFmpeg/ffprobe, плейлист из двух медиа, VTT-субтитры, очередность, повтор без дубля, отмена queued/active, продолжение очереди, PlainText удалённых названий и остановка потомка, игнорирующего SIGTERM.
- `ruff check .`: все проверки пройдены.
- `python scripts/build.py`: Linux-сборка PyInstaller завершена. Основной GUI и отдельный worker находятся в `~/.cache/videodock-build/dist/VideoDock` (около 279 MiB).
- Пять worker-интеграций запущены повторно с `VIDEODOCK_TEST_WORKER=.../VideoDock/_internal/worker/VideoDockWorker/VideoDockWorker`: **5 passed**. Это проверяет настоящий собранный исполняемый файл, а не исходный модуль.
- Внешняя загрузка YouTube `jNQXAC9IVRw` («Me at the zoo») через source worker: exit 0, готовый MP4, `ffprobe` подтвердил 19.014 секунды, видео 320×240 (AV1) и аудио Opus. Качество 480 - верхняя граница, более высокого источника для данного выбора не было. Проверка не распространяется на все ролики и сайты.
- Та же внешняя загрузка повторена через собранный worker в отдельный новый каталог: exit 0, `file` и `done(count=1)`. Это дополнительно проверяет упаковку yt-dlp/EJS, а не только локальный HTTP fixture.
- Тестовый адрес `BaW_jenozKc` вернул «This video is unavailable», это корректно показанная ошибка, а не доказательство сетевой поломки. Проверку продолжили на доступном ролике.
- Установлен ярлык `~/.local/share/applications/videodock.desktop`; иконка сгенерирована собственным QPainter. Настройки первого запуска направлены в Dropbox `Моя папка/Видосы/VideoDock`.
- Запуск GUI из оболочки инструмента сначала завершился ошибкой отсутствующего display. Запуск в существующем Wayland-сеансе с фактическим сокетом `/run/user/1000/wayland-1` оставил GUI-процесс работающим. Это проверка запуска процесса, а не ручной проход кнопок.
- [preview-linux.png](preview-linux.png) - снимок Qt offscreen с тестовой записью о реально загруженном медиа. Это рендер окна для визуальной инспекции, не снимок рабочего стола.
- `sh -n` прошёл для обеих установочных задач `claude-shared/once/{linux,darwin}/2026-11-03-videodock.sh`. Задача macOS устанавливает зависимости и ярлык без вопросов при следующем автоматическом прогоне.

## Безопасность: собственный код

Применён офлайн-проход code-audit по всему production Python и установочным скриптам. Границы: ссылки/названия от сайтов, аргументы запуска worker и FFmpeg, SQLite, открытие файлов, локальные пути, процессные группы, зависимости. Приложение не слушает сетевые порты, не имеет сервера/авторизации и не публикует пользовательскую историю. Поэтому проверка страниц/API без cookies к нему неприменима. Загрузка по произвольному HTTP(S)-адресу выполняется локальным пользовательским клиентом и по его явному вводу.

- Gitleaks: **no leaks found**.
- pip-audit: проверено **49 установленных пакетов**, известных уязвимостей не обнаружено на момент запуска. Это не доказательство отсутствия неизвестных уязвимостей в библиотеках или медиапарсерах.
- Bandit: 9 предупреждений, 0 high. B608 проверен отдельным свежим агентом: имена SQL-полей ограничены whitelist, все значения параметризованы; вредоносные имена отвергнуты, значения сохранены буквально. B404/B603: фиксированные исполняемые команды, argv-массивы, shell не включён; статический `-c` установщика не содержит пользовательской подстановки. Для проверенных путей это false positives.
- Свежий агент динамически проверил PlainText, блокировку открытия файлов вне каталога (включая symlink), границу output worker и безопасные пути `prepare_filename` yt-dlp.
- Подтверждённая находка: после SIGTERM worker его потомок, игнорирующий сигнал, оставался жив. Регрессионный тест сначала упал; исправление сохраняет принадлежащий worker PGID и завершает остаток группы после exit worker. Независимый повтор подтвердил исчезновение worker, прекращение потомка, сохранение `cancelled` и безопасную работу отложенного таймера. Полный набор свежий агент также выполнил: **24 passed**. Открытых подтверждённых находок в проверенном исходнике не осталось.

Полные локальные результаты: `~/.local/share/videodock/research/{rea-evidence.json,build.log,pip-audit.json,bandit.json,gitleaks.json,youtube-worker.jsonl}`. Пользовательские базы, cookies и ключи оригинального 4K не читались.

## Что ещё не проверено

Native computer use недоступен: CUA вернул пустой список приложений. Qt offscreen и процесс, оставленный в Wayland, не заменяют ручную проверку системного выбора папки, проигрывателя, открытия папки и взаимодействия с рабочим столом. На macOS/Windows исходники и установочные/сборочные пути подготовлены, но реального запуска/сборки на этих ОС в этом сеансе не было. Установочный job macOS ещё должен автоматически выполниться на маке.

Не проверены реальные YouTube 4K-потоки, живой большой плейлист, приватные ролики, вход в аккаунты, редкие сетевые сбои и все варианты системных медиапроигрывателей. Для первых трёх есть настройки и локальные проверки соответствующих механизмов; поддержки авторизации в этой версии нет. FFmpeg/Node.js устанавливаются отдельно. Автоматическое обновление extractors, подписки на каналы и точное соответствие всем функциям 4K Video Downloader+ не реализованы.
