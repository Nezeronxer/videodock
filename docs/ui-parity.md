## Оформление

`UiTheme.qml` задаёт общую палитру для всех экранов. Настройка `theme` принимает только `dark`, `light`, `system`, сохраняется в SQLite и применяется без перезапуска. Для новых и существующих профилей без этой настройки используется тёмная тема. `system` следует `Qt.styleHints.colorScheme`.

Наблюдаемые dark colors: accent `#5FB21F`, window `#292929`, toolbar/строки `#333333`, list `#262626`, popup `#383838`, control panel `#3C3C3C`, selection `#383C40`. Источники: `app-qml/Gui/Theme.qml:8`, `bundle-9959a50/Okna/Qml/openmedia/gui/okna/Palette.qml:27–59,87–102`. У оригинала основной текст зависит от SystemPalette; в VideoDock текст и вторичные подписи выбраны с проверяемым контрастом. Ошибка осветлена относительно оригинала для читаемости на тёмном фоне.

`AppDialog.qml` объединяет палитру и стандартные кнопки диалогов. Английские и русские строки приложения встроены; стандартные кнопки дополнительно используют системные переводы Qt. Иконки действий и сервисов находятся в `qml/icons/`, нарисованы для проекта и включены через QRC.

## Проверка

```sh
sh crates/desktop/tests/check-appearance.sh /absolute/path/to/screenshots ru
sh crates/desktop/tests/check-appearance.sh /absolute/path/to/screenshots en
CARGO_BUILD_JOBS=2 CARGO_TARGET_DIR="$HOME/.cache/videodock-rust-target" cargo test --workspace --offline
CARGO_BUILD_JOBS=2 CARGO_TARGET_DIR="$HOME/.cache/videodock-rust-target" cargo clippy --workspace --all-targets --offline --no-deps -- -D warnings
```

Qt harness загружает реальные QML приложения, подменяя только Backend синтетическим QObject. Он проверяет тёмное/светлое/системное оформление, пять вкладок настроек, десять диалогов, меню, стандартную кнопку закрытия, раскрытие/сворачивание браузера, 880 px ширину, контраст текста и выбор 720p до фактического dispatch. Для одиночного и пакетного выбора создаются отдельные рендеры. Входы, cookies, пользовательская база и сеть не используются.

Дополнительный этап подключает тот же Qt frontend к настоящему Rust `Engine` через тестовый JSON-lines процесс `crates/core/examples/ui_engine.rs`. Проверены смена темы и перезапуск, отображение нормализованного лимита скорости, отказ при неверном host/port прокси и сохранение корректных полей. Затем QML получает ссылку на локальный HTTP fixture с настоящим MP4, открывает ручной выбор и отправляет загрузку. Проверяются состояние `complete`, две дорожки через ffprobe, сохранённая история после перезапуска и сброс временного лимита скорости. Контекстное меню копирует исходную ссылку; отмена удаления сохраняет историю и файл, подтверждение без флажка удаляет только запись. Используются одноразовый профиль и loopback-сервер; пользовательские данные и внешние сервисы не затрагиваются. Это проверка QML/core через тестовый транспорт, не живой desktop и не проверка native cookie bridge.

При этой проверке воспроизведены и устранены три дефекта:

- Выбор контейнера MP4 скрывал форматы: фильтр сравнивал `MP4` с `mp4`. Сравнение теперь не зависит от регистра.
- После выбора `1 Mbps` Engine сохранял `125000` байт/с, а ComboBox показывал `Unlimited`: отсутствовало обратное преобразование единиц. Добавлено преобразование Mbps/kbps/B/s; значение вне предложенного списка показывается явно.
- Подтверждение стандартной кнопки вызывалось дважды: Qt уже связывает DialogButtonBox с Dialog, а AppDialog повторял это вручную. После первого удаления UI очищал selection, и второй dispatch уходил с пустыми `ids` (в core это вся история). Повторные accept/reject-связи удалены. Диалог удаления дополнительно копирует выбранные ID при открытии и расходует этот набор перед отправкой; пустой набор ничего не удаляет. Реальный тест создаёт две загрузки, отменяет первый диалог, затем удаляет только одну запись, меняя текущую selection, и повторно вызывает accept: соседняя запись и оба файла должны сохраниться.

## Живой проход после восстановления CUA

Продолжение 03.11.2026: реальный X11/XWayland desktop через штатный Linux Sky, `cua_repl`, AT-SPI и снимки окна. Запущен собранный Rust/CXX-Qt бинарь с отдельным `VIDEODOCK_DATA_DIR`; установленный Python-прототип и пользовательские данные не заменялись.

- Пройдены пять шагов обучения, Next/Back/Skip/Finish, пять вкладок настроек, смена light/dark и штатный Quit/restart. Сохранённая тема и завершённое обучение пережили перезапуск.
- Встроенный браузер открыл loopback MP4; кнопка Download вызвала реальный ручной разбор, показала найденный формат и дорожку; Cancel вернул список без второй загрузки. Тот же перевод подписей применён к пяти ручным фильтрам без изменения их canonical значений.
- Настоящее меню File экспортировало пустую историю: JSON проверен парсером. Импорт `{}` остался открытым с ошибкой схемы и не добавил строк. Затем импортирован один loopback URL с отдельной папкой результата.
- Реальное действие GUI → Rust Engine → HTTP loopback → FFmpeg завершилось состоянием «Готово». `ffprobe` подтвердил H.264+AAC; запись и файл сохранились после штатного перезапуска. Открыты контекстное меню и сведения; значения типа и состояния показаны по-русски.
- Оригинальный EXE запущен напрямую с новым Wine prefix, без PortableApps launcher, без чтения пользовательских Data/аккаунтов/истории. Снят его экран обучения. SHA-256 EXE после запуска совпал с исходным. Wine не реагировал на доступные фоновые клики и клавиши CUA; остальные экраны оригинала этим проходом не проверены. Новый Wine runtime остановлен, тестовый профиль оставлен на диске.

Найденные и исправленные расхождения:

- Обучение было маленьким затемняющим диалогом. Теперь оно занимает всю клиентскую область; карточка шириной до611px, область иллюстрации265px и действия100×40 повторяют наблюдаемую геометрию. Иллюстрации собственные. На первом шаге Skip, далее Back, на последнем Finish; завершение сохраняется прежней командой Engine.
- У кнопки Next терялся зелёный фон после применения Qt Basic palette. Заданы соответствующие роли Basic (`dark` для primary, `windowText` для flat secondary); сохранён нижний отступ16px.
- В русских настройках показывались `video`, `Any`, `Unlimited`, `1 day`, а в сведениях `complete`. Подписи переведены отдельно от исходных значений: выбор Audio по-прежнему отправляет `mediaType: audio`, единицы и валидация core не менялись. В QM299 завершённых переводов.

Regression runner сначала воспроизвёл каждый нетривиальный дефект (полноразмерный экран, внутреннее имя типа, потеря accent, непереведённые ручные фильтры), затем прошёл с исправлениями. Дополнительные проверки проходят реальные Next/Back/Skip/Finish, проверяют пиксель accent-фона и сохранение исходного значения протокола после выбора переведённой подписи. Основные Qt/core сценарии, узкое окно, стандартные Close и безопасное удаление остаются в том же runner.

Доказательства: `~/.local/share/videodock/research/live-ui-2026-11-03/`: `original-onboarding.png`, `verified-dark-home.png`, `verified-dark-onboarding.png`, `verified-dark-manual.png`, `delivery-dark-details.png`, `native-download-complete.png`, `native-ffprobe.json`, AX и журналы regression/build/workspace. ## Продолжение с native Linux reference

Оригинал 26.3.5.0396 извлечён из официального cached archive с проверенным SHA-256. Он запускается с отдельными XDG config/data/cache. Последнее сравнение сделано при одинаковом размере 1703×1336, английском языке и тёмном оформлении. После замечания пользователя оба тестовых окна закреплены за обычным пустым столом 90; запуски используют `workspace="90 silent"`. Пользовательский стол не переключается, special не используется. Qt-регрессии выполняются в отдельном Xvfb.

Восстановлен потерянный при переделке настроек переключатель темы: View → Appearance → Dark/Light/System. Меню вызывает существующую проверяемую настройку; выбор и отметка активного пункта проверены кликами Qt, сохранение после перезапуска - с настоящим Engine и отдельным нативным CUA-запуском. Это собственное расширение для согласованного выбора оформления; платные экраны исключены пользователем.

Парные живые снимки выявили и помогли исправить смещение пустого заголовка: у оригинала между двумя подписями нет дополнительного интервала, а вертикальное положение зависит от фактической высоты браузера. В строке браузера восстановлены поиск с отступом 38 px и навигационные иконки 20 px; исправлен фон недоступной Search. В General сопоставлены основная dark-поверхность `#242424`, sidebar `#2b2b2b`, выбранный раздел `#333333` и значки разделов. Размер, положение диалога и основные координаты совпадают в проверенном состоянии; параметры оригинала вроде автообновления и запуска в фоне в наш профиль не копировались.

Локальный исследовательский `appearance.rcc` содержит только изображения, разрешённые bridge по basename. Он находится вне исходников и не входит в открытую поставку. В отсутствие pack используются собственные иконки. Обе ветки проверены: RU с pack и EN без него. Каталог исходных меню содержит 71 вариант субтитров и 72 варианта аудиодорожек; длинное меню проверяется с прокруткой до реального отображения пункта. Русский QM содержит 319 завершённых переводов, незавершённых нет.

Свежие результаты: 136 Rust tests passed, 0 failed, 21 ignored; Qt с настоящим Engine, restart, настройки, локальная загрузка до ffprobe, сохранённая история и безопасное удаление прошли. Дополнительно исправлены тестовые условия: отдельная `state/` внутри временного HOME и ожидание геометрии после resize. Неточные клики теста по ещё не показанным пунктам не описываются как дефект приложения.

## Что ещё не доказано

Сопоставление нескольких живых экранов и статических ресурсов не доказывает пиксельного совпадения всей программы. Полный парный обход состояний оригинала остаётся открытым; его Linux-копия отвечает на ввод, ограничение Wine относится только к раннему этапу. Нативные Wayland окна, tray/системные уведомления/автозапуск, аккаунты, все файловые диалоги и реальные macOS/Windows остаются непроверенными. Собственные иллюстрации не воспроизводят фирменные анимации. Исследовательский appearance pack не заменяет собственную переносимую графику поставки. Остальные функциональные пробелы остаются в [матрице](feature-matrix.md).
